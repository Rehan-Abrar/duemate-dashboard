# DueMate UI Rules

Version 2.0

---

# Core Philosophy

Every screen should answer exactly one user question.

Every interaction should feel:

• Simple
• Intentional
• Helpful
• Calm

DueMate should reduce academic stress, not create more complexity.

---

# User Experience Principle

The user should always understand:

1. What is happening
2. What requires attention
3. What action to take next

Never make users search for important information.

---

# Landing Page

Question:

"What is DueMate and why should I use it?"

Prioritize:

• Clear product explanation
• AI value proposition
• WhatsApp reminder benefit
• Strong primary CTA
• Realistic product preview

Hero should communicate within 5 seconds:

• What DueMate does
• Who it is for
• Why it is useful

Avoid:

• Generic SaaS hero sections
• Excessive animations
• Long explanations
• Feature overload

---

# Onboarding

Question:

"How do I start using DueMate?"

Prioritize:

• Simple setup flow
• WhatsApp connection
• Student information
• Academic preferences

Rules:

• Keep steps minimal
• Show progress
• Avoid unnecessary forms

---

# Dashboard

Question:

"What needs my attention today?"

Prioritize:

1. Today's Focus

2. Upcoming deadlines

3. AI recommendations

4. Recent activity

Should highlight:

• Important assignments
• Exams
• Quizzes
• Urgent deadlines

Avoid:

• Large tables
• Complex analytics
• Business-style dashboards
• Too many widgets

The dashboard should feel like a personal assistant, not a data portal.

---

# Tasks

Question:

"What do I need to complete?"

Prioritize:

• Task cards
• Due dates
• Course information
• Priority
• Completion status

Support:

• Search
• Filtering
• Grouping

Avoid:

• Spreadsheet layouts
• Excessive statistics
• Complex project management features

---

# Calendar

Question:

"When is everything happening?"

Prioritize:

Mobile:

• Agenda view
• Timeline view

Desktop:

• Month view
• Agenda view
• Timeline view

Show:

• Assignments
• Exams
• Presentations
• Academic events

Avoid:

• Overcrowded calendars
• Too many colors

---

# AI Assistant

Question:

"How can DueMate help me?"

The AI assistant should feel like:

A helpful academic companion.

Not:

A customer support chatbot.

Prioritize:

• Natural conversation
• Suggested prompts
• Quick actions
• Context-aware answers

Examples:

"Show my deadlines this week"

"When is my next exam?"

"Plan my study schedule"

Avoid:

• Robotic chat layouts
• Generic chatbot bubbles
• Support ticket appearance

---

# Settings

Question:

"How do I manage my account?"

Keep simple.

Include:

• Profile
• Notifications
• WhatsApp connection
• Preferences
• Account options

Avoid:

• Complex configuration panels

---

# Screen Hierarchy

Every screen should follow:

Primary Navigation

↓

Page Purpose

↓

Main Action

↓

Important Information

↓

Secondary Information

↓

Supporting Options

---

# Information Priority

Always prioritize:

Urgent academic information

over

Secondary details.

Example:

Deadline date

comes before

Task metadata.

---

# Primary Actions

Only ONE primary action per screen.

Examples:

Create Task

Connect WhatsApp

Complete Task

Ask AI

Save Changes

Everything else should be secondary.

---

# Mobile Interaction Rules

Design for thumb-friendly use.

Requirements:

• Minimum button height: 48px
• Comfortable spacing
• Large touch areas
• Avoid tiny controls

Important actions should be reachable easily.

---

# Neumorphic UI Rules

Use neumorphism carefully.

Prefer:

• Soft surfaces
• Subtle depth
• Gentle shadows
• Clear hierarchy

Avoid:

• Excessive 3D effects
• Floating everything
• Low contrast text
• Decorative shadows

Depth should communicate meaning.

---

# Color Usage

## Electric Blue

Use for:

• Primary actions
• Links
• Important highlights
• AI indicators

---

## Red

Use for:

• Errors
• Overdue tasks
• Delete actions

---

## Orange

Use for:

• Warnings
• Upcoming urgency

---

## Green

Use for:

• Completed tasks
• Success states

---

## Gray

Use for:

• Secondary information
• Supporting text

---

# Icons

Use:

Lucide icons.

Rules:

• Pair icons with labels where possible
• Avoid icon-only navigation
• Maintain consistent stroke style

Icons should improve understanding.

---

# Typography Rules

Text should be:

• Short
• Clear
• Human
• Scannable

Avoid:

• Long paragraphs
• Technical language
• Complex explanations

---

# Forms

Rules:

• Prefer single-column layouts
• Labels above fields
• Clear validation messages
• Minimal required inputs

Avoid:

• Long registration forms
• Unnecessary fields

---

# Tables

Avoid tables whenever cards can communicate better.

Prefer:

• Cards
• Lists
• Timeline layouts

Tables should only be used when comparing structured data.

---

# Empty States

Every empty state requires:

1. Simple visual

2. Helpful message

3. Clear CTA

Example:

"No upcoming deadlines"

"Add your first assignment to start tracking your semester."

[Add Task]

Never show empty screens.

---

# Loading States

Use:

Skeleton loading.

Avoid:

• Blank screens
• Excessive spinners

Loading should maintain layout continuity.

---

# Responsive Rules

Mobile first.

Then:

Tablet adaptive.

Desktop expanded.

Rules:

• No hidden core functionality
• Maintain hierarchy across devices
• Preserve touch-friendly interactions

---

# Accessibility

Requirements:

• WCAG AA contrast
• Keyboard accessibility on desktop
• Visible focus states
• Minimum button height: 48px
• Readable typography
• Clear error states

---

# Final Quality Test

A first-time student should understand DueMate within 30 seconds.

They should know:

• What it does
• Why it helps
• What to do next

If a feature requires explanation, simplify the design.
