# DueMate Design System

Version 2.0

---

# Design Philosophy

DueMate follows a:

Mobile-first
Modern Neumorphic
AI Productivity

design system.

The interface should feel:

• Calm
• Intelligent
• Premium
• Personal
• Effortless

Every component should look like part of a polished AI startup product.

---

# Layout System

## Responsive Strategy

Mobile First

Primary viewport:

390 × 844 px

Secondary:

Tablet

Desktop

All layouts should scale upward from mobile while preserving spacing, hierarchy, and visual language.

---

24px

# Mobile Layout

Screen padding:

20px

Section spacing:

48px

Card spacing:

16px

Content width:

100%

Avoid cramped layouts.

Prioritize:

• Readability
• Touch targets
• Vertical scrolling
• Clear hierarchy

# Desktop Layout

Maximum width:

1200px

Horizontal padding:

32px

Desktop should feel like an expanded mobile experience, not a separate product.

# Surface System

DueMate uses modern neumorphic surfaces.

---

# Raised Surface

Used for:

• Cards
• Buttons
• Feature blocks
• Dashboard widgets

Appearance:

Soft elevated surface.

Characteristics:

• Rounded corners
• Gentle shadows
• No harsh borders

---

# Inset Surface

Used for:

• Inputs
• Search
• Selected states

Appearance:

Pressed into background.

# Dashboard Structure

The dashboard should prioritize student productivity.

Order:

1. Today's Focus

2. Upcoming Deadlines

3. Academic Overview

4. AI Insights

5. Recent Activity

Avoid unnecessary widgets.

---

# Today's Focus Component

Primary dashboard element.

Shows:

• Most important task
• Deadline
• Priority
• Quick action

Should feel like a personal assistant recommendation.

---

# AI Assistant

The AI assistant is a core DueMate feature.

Design:

Large conversation area.

Contains:

• Chat messages
• Suggested prompts
• Conversation history
• Quick actions

Style:

Friendly AI companion.

Avoid robotic chatbot appearance.

# Empty States

Every empty state must contain:

• Simple visual
• One helpful sentence
• One clear CTA

Never show blank screens.

---

# Loading States

Skeleton loading

# Component Rules

Every component must:

• Be reusable
• Have clear hierarchy
• Support mobile interaction

• Feel production-ready
